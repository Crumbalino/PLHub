The organizing fact

This project spans a rebrand. Everything below was built as PLHub (plhub.co.uk) up through late Feb/early March, then the site became The Football Hub (thefootballhub.uk) — new navy/pink/teal palette, Sora + JetBrains Mono type, the diagonal bracket logo, the Hub Index scoring system. tfh-future-proofing-spec.docx even contains an explicit "Rebrand Switchover Checklist." The two eras below aren't just chronological — the TFH docs are the current source of truth, and most PLHub docs are either fully superseded or hold content that hasn't been migrated yet. That split is the main thing to work from when deciding what to keep.

Five things worth a decision

01 · Exact duplicate

tfh-brand-v6.html is uploaded twice

Same file, same content, two upload timestamps a minute apart (23:17 and 23:18 on 11 Mar). No reason to keep both.

Recommendation: delete one copy. Zero risk — it's a byte-for-byte duplicate.
02 · Superseded draft

"PL hub feature backlog" vs. PLHub-Feature-Backlog.md

The unnamed-extension file is an earlier, rougher draft of the same backlog — same content, less organized, with a stray link and a note-to-self left in.

Recommendation: delete "PL hub feature backlog" once you've confirmed nothing in it is missing from the cleaned-up version.
03 · Likely absorbed

PLHub-Tone-of-Voice-v2.docx vs. PLHub-Brand-Voice-v2.docx

The standalone tone-of-voice doc reads as a subset of Brand-Voice-v2's own Tone of Voice section — same rules, same examples, no additions found.

Recommendation: worth a side-by-side skim before deleting, but this looks safe to fold into the master doc.
04 · Doc/code duplication

Six .tsx files exist twice — as prose prompts and as code

PLHub-Claude-Code-Prompts-TOV-v2.docx contains the same component code as PageLayout.tsx, about-page.tsx, how-it-works-page.tsx, principles-page.tsx, contact-page.tsx and Footer.tsx, written out as build prompts.

Recommendation: keep the standalone .tsx files (they're the usable form); the Prompts doc is now mostly historical record of how they were built — fine to archive rather than keep in active project knowledge.
05 · Conflicting spec

tfh-frontend-redesign-brief.md's card system doesn't match the current build

Its Story/Stat/Quote/Result/LOL/Rumour taxonomy and gamification layer (badges, confetti) aren't present in tfh-feed-v5.jsx or tfh-card-interaction-spec.md, which use a different card set entirely.

Recommendation: confirm with yourself whether this brief was superseded or just never implemented — the doc itself says not to build from it until you'd signed off, so it may be worth archiving rather than deleting outright.
